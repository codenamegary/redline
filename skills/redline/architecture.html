redline · architecture · v4

The review turn belongs to redline

This is now shipped. The user's coding agent no longer blocks on a wait loop: it creates the artifact, shares the URL, and stops. redline owns two lanes: a reviewer for thread replies, and a worker for HTML on Iterate. Each lane has its own adapter, model, and prompt template. The origin chat is optional notify only. HTML loads once into the worker session. Comments after that ship threads, not the document.

Decision

Reviewer lane

Thread replies

A comment starts the reviewer. redline fills the prompt template and PATCHes each thinking placeholder. Match length to the ask. An instruction gets a short ack. A question gets a thorough answer.

  • No HTML. No tools.
  • Own adapter and model (often a small cheap one).
  • One reviewer job per artifact at a time.
Worker lane

HTML on Iterate

Iterate starts a fresh worker with artifact HTML plus the frozen batch. The worker returns a complete document. redline POSTs /versions. Same publish gate as today (409 unless iterating).

  • Stable ids. Inline CSS/JS. Use hosted libraries for interactivity (Tailwind CDN, jQuery, etc). Short note of what changed.
  • Own adapter and model (often a stronger one).
  • Does not run in the origin chat.
Notify

origin session stays idle

If create came from a supported host, store origin (host, session id, server URL). After a duty, optionally post a one-line status. Never wait there. Never dump the reply body.

  • Example: v3 published · 3 threads still open
  • Missing origin: skip notify. User lives in the browser.
  • Coming back later still knows the artifact id from create.

Do not put Task or background-subagent waits in the skill. Do not ACP into the user's TUI session. ACP is for reviewer and worker sessions redline spawns. HTTP/SDK notify is for the origin chat only.

Software architecture

A host adapter is the only place that knows how to talk to an agent product. The dispatcher is host-blind. Reviewer and worker each hold an adapter id plus command/model. They may share ACP and still use different binaries or models. Notify is a separate optional method on adapters that can inject an origin session.

Worker session

When a worker starts for an artifact, create a fresh host session and put the current HTML in it once (ACP resource or first message with the document). Then send the frozen batch and "return a complete HTML document." Do not resend the full HTML on every comment. Comments use the reviewer lane. Reviewer sessions get threads and the prompt only.

  • Each Iterate is a fresh worker. New session. Seed current HTML. Discard after publish.
  • Reviewer session may stay bound while the artifact is in review. Crash or disable unbinds it. Idle reviewer does not occupy the origin chat.
  • Queue per artifact per lane. A second comment while a reply is in flight shares or waits on the thinking placeholder (same rule as today).

Prompt templates

Settings store two templates, one per lane. Ship defaults. User can edit. Substitutions: {{prompt}} (the original create instruction, the artifact's prompt field), {{title}}, {{version}}, {{threads}}, {{batch}}.

Both defaults steer language: plain words, short sentences, facts. No semicolons. No em dashes. No hedging. No filler.

Presence and fallback

agentAttached means redline can answer. Sources: a bound reviewer, a running worker, or an in-flight ?wait= long-poll (HTTP only, kept for debugging and raw clients). No host plugin registers a wait tool.

OpenCode / pi create_artifact passes origin when the execute context has a session id. If the plugin context lacks it, add a filled-in argument. After create, never call wait. Return the review URL and stop.

Skill change

  1. Author HTML. Call create_artifact. Give the user the URL. Stop.
  2. Live replies and Iterate happen in the browser, on the server's lanes.
  3. Optional: user returns to the origin chat. That chat already has the artifact id from step 1. Notify lines are extra, not required for awareness.
